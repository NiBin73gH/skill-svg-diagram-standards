# 泳道框架图布局规范（硬性数值）

所有数值来自 2026-08-21 用户逐项确认的版本。它们是对应版式的默认硬约束；
不要把某一种版式的画布尺寸机械套到所有图。

## 1. 画布与 SVG 外壳

- 标准多泳道总览图使用 viewBox 宽 1180，内容左右各留 16px 边距。
- 普通横向、纵向和小型控制流按内容确定宽度，采用 §8 的节奏；不得为了满足
  1180px 而制造大片空白或压缩节点。
- 高度按内容加底部约 20px；所有节点、线段、标签均须在 viewBox 内。
- 背景 `#fbfcfe`（`.bg` rect 铺满）。
- 每个 SVG 必须有 `viewBox`、`role="img"`、`title`、`desc`、`aria-labelledby`；
  ID 使用图名前缀并在整个 HTML 内唯一。完整要求见 `delivery-contract.md`。

## 2. 泳道横带（band）

| 项 | 值 |
|----|----|
| 位置 | x=16，w=画布宽-32，rx=12 |
| 样式 | 虚线边框 `#94a3b8` 1.2px dasharray 6 4，填充 `#f8fafc` |
| 标题 | 基线 = band_y+23，x = band_x+16，14px 加粗 `#475569`，左对齐 |
| **节点顶** | **band_y+48**（标题基线下净空约 25px）——硬性，曾因 1~3px 贴边被用户打回 |
| 节点底到带底 | ≥14px（矮带 14px，高带 32~38px） |
| 带高 | 由节点布局反推：h = 48 + 节点高 + 底部余量；不要先定带高再塞节点 |
| 带间间隙 | 默认 20px；**有跨层连线且带标签穿过的间隙用 44px**（标签 11px 高 + 上下净空） |

## 3. 节点（box）

| 项 | 值 |
|----|----|
| 文字 | 12.5px，行高 18px；多行用 tspan 显式 y/dy 定位（禁用 dominant-baseline，cairosvg 不支持） |
| 高度 | 自动：`行数×18 + 2×8`（VPAD=8）——**不要手算高度** |
| 宽度 | 文字 CJK 感知估宽（CJK≈1em、ASCII≈0.6em、空格≈0.3em，×12.5px）+ 2×13（HPAD）须 ≤ 框宽 |
| 圆角 | rx 8 |
| 首行基线 | y + VPAD + 11 |

节点配色（填充/边框，1.4~1.5px 边框）：

| class | 用途 | 填充 | 边框 |
|-------|------|------|------|
| app | 应用层：App 与直接面向用户的功能 | #dbeafe | #2563eb |
| hal | HAL/用户态框架：CamX、CHI、Provider 等处理逻辑 | #dcfce7 | #16a34a |
| kernel | 内核/驱动：camera.ko、V4L2、CCI 等实现 | #ffedd5 | #ea580c |
| sensor | 外设/传感器：外部解码器、Sensor 等器件 | #e0e7ff | #4f46e5 |
| hw | SoC 硬件：CSIPHY、CSID、TFE、OPE、GPIO 等资源 | #fae8ff | #a21caf |
| api | 接口/配置契约：属性、XML、API、元数据及约束 | #fef9c3 | #ca8a04 |
| node | 中性逻辑/框架输出：不归属特定硬件层的节点或结果 | #e0f2fe | #0284c7 |
| sink | 输出/终点：预览、录像、Surface 等最终输出 | #f1f5f9 | #64748b |
| build | 构建/生成物：构建配置、打包过程及生成文件 | #e2e8f0 | #475569 |
| disabled | 已禁用：关闭、禁用或绕过的模块 | #fee2e2（虚线边框） | #dc2626 |
| note | 可选/说明：可选路径、补充说明或注意事项 | #fff7ed（虚线边框） | #ea580c |

同一个 class 在整套文档中保持同一语义。不同视角、阶段、左右栏或执行顺序使用标题、
泳道和箭头表达，不借用节点颜色区分。

## 4. 连线（edge）

- **全部正交折线**；端点一律锚点函数：`d.top/bottom/left/right(id, dx=0)`。
- 线型语义与样式：

| cls | 含义 | 样式 | 箭头 |
|-----|------|------|------|
| `""` | 控制面/命令 | #64748b 1.8px 实线 | 灰 |
| `data` | 数据面（像素/音频） | #0284c7 2.2px 实线 | 蓝 |
| `up` | 带外/上行回读 | #d97706 实线 dasharray 6 4 | 橙 |
| `link` | 关联关系 | #94a3b8 dasharray 5 4 | 无 |

- 标签：11px `#334155` 加粗，放连线上方 5~7px（基线距线），多行 dy=13.5；
  距上下泳道边界线 ≥3px；anchor start/middle 按位置选。
- **竖线进入泳道带时不得压带标题**：标题占 x ∈ [band_x+16, band_x+16+估宽]，
  估宽 ≈ CJK字数×14 + ASCII字数×8.4；进入点落在估宽右界之外，否则绕行
  （典型做法：先横移到标题右侧再竖直进入）。
- 双向关系（如 CHI-CDK↔CamX）画两条平行短箭头（相距 ~38px），各自标一个方向
  的含义。

## 5. 两级图例与辅助文字

### 5.1 每张 SVG 的简洁图例

- 放在图顶部独立浅灰容器内，先画图例再整体下移正文，图例不覆盖节点或连线。
- 分“底色”和“连线”两行；只列当前图实际使用的 class/线型，超宽时自动换行。
- 色块为 16×12px、圆角 3px；文字 11px。`disabled`、`note` 保留虚线边框。
- 连线样例保持 §4 的颜色、粗细、虚实与箭头语义。
- SVG `<desc>` 同步写入本图实际使用的节点颜色语义。
- 图例由生成器根据节点/边 class 自动推导，不使用 `d.text()` 手写图例。

### 5.2 每篇 HTML 的文末完整色块说明

- 每篇生成的 HTML（包括没有流程图的页面）在 `</article>` 前恰好加入一份：
  `<section class="color-key" aria-labelledby="flow-color-key-title">`。
- 标题固定为“流程图色块说明”，列出 §3 的完整节点配色。
- 开头固定说明：`色块仅用于区分模块的职责或技术层级，不表示执行顺序、成功/失败或数据格式。`
- 每项包含实际色块、语义名称和一句简要解释；桌面端两列、窄屏单列。
- 图内图例与文末说明从同一份配色语义数据生成。

### 5.3 辅助文字

自由注释文字用 `d.text(x, y, s, cls, anchor, size)`，不用节点承载注释。

## 6. 自检清单（生成器内置，必须全 OK）

1. HTML 无外部加载资源或运行时渲染回退；namespace URL 例外；
2. 每个 `<svg>` 可被 XML 解析，具备 title/desc/aria-labelledby，无重复或悬空 ID；
3. 无 dominant-baseline；节点文字估宽不溢出框宽-6；
4. 折线不穿过任何节点收缩框（rx+2 内缩 2px）内部；
5. 所有线段正交（无斜线）；
6. 节点、线段、标签和图例都在画布范围内；
7. FLOWCHART 标记、源图块、SVG 与生成 HTML 中图数一致；
8. 每张 SVG 恰有一份图例，图例记录的节点/边 class 集合与图中实际集合相等；
9. 每篇 HTML 恰有一份文末 `color-key`，并包含 §3 的全部节点类别；
10. 图内图例、文末说明和节点 CSS 使用同一配色语义；
11. 任何失败均返回非零退出码，不得只输出 WARN 后继续成功。

## 7. 视觉验证检查单（渲染 PNG 后逐项问视觉模型）

1. 每个泳道带标题与带内节点顶部之间是否有清晰空隙（目标 ~25px）？
2. 节点底部与带底边界是否不贴边？
3. 层间间隙（有连线的 44px 处）标签是否与上下边界线、相邻标签无重叠？
4. 连线是否压住任何带标题文字？
5. 节点文字是否溢出/截断？标签之间是否遮挡？
6. 图例是否完整可读？整体布局是否均衡（无大片空白/越界）？
7. 缩窄页面后是否可横向滚动而不截断？打印预览是否保持图的可读比例？
8. HTML 文末色块说明是否为桌面两列、窄屏单列，色块与文字是否对齐？

渲染方法：安装 cairosvg 后执行
`python3 -c "import cairosvg; cairosvg.svg2png(url='in.svg', write_to='out.png', output_width=1500)"`。
安装命令按平台选择：Debian/Ubuntu（PEP 668 管控）用
`pip3 install --user --break-system-packages cairosvg`；其他平台去掉
`--break-system-packages`，或直接在 venv 里 `pip install cairosvg`。

## 8. 流程图版式规范（2026-08-21 第二轮确认）

### 8.1 横向 / 纵向选型

| 条件 | 版式 |
|------|------|
| 主链节点 ≤7、单行排开、无阶段分组 | 横向 LR（节点一行，y 居中对齐，行高统一） |
| 步骤 ≥8 或有阶段语义（一次/每帧等） | 纵向 TD + 阶段泳带（阶段名写在泳带标题里，不另加文字） |
| 管线图：选择头 + N 级串联 + 末端分叉到多个 Target/Surface | 纵向；选择头（api 类）→ 串联链（蓝数据边）→ 末端左右分叉 |
| 一分二/一分多的小控制流 | 横向小图（全图 ≤4 节点，画布 ~1150×250） |

横向主链参数：节点高统一 52（两行）或 34（一行）并按最高者对齐中线；默认间隙
36~40px；**有边标签的间隙 = 标签估宽 + 12px**（标签 11px 字号，估宽同 §3 的
CJK/ASCII 规则换算）。画布宽 ~1480（对齐 audio"一分钟"模版）。

### 8.2 分叉路由（硬规则）

分叉/汇合必须写全拐点，禁止直连锚点或用偏移量凑坐标：

```python
# ✅ 先水平到目标 x（同一 y），再竖直进入目标锚点
d.edge([d.bottom("s5"), (370, 448), (210, 448), d.top("t1")], cls="data")
d.edge([(370, 448), (660, 448), d.top("t2")], cls="data")   # 共用拐点 (370,448)
# ❌ 直连锚点 = 斜线段（自检报"非正交线段"）
d.edge([(370, 448), d.top("t2")], cls="data")
# ❌ 用锚点偏移量凑目标 x，必然算错
d.edge([(370, 448), d.top("t1", -160)], cls="data")
```

分支标签放在分支水平段上方/下方，估宽不得压到分支目标节点框。

### 8.3 可选节点与绕行边

- 可选步骤：节点用 `note` 类（橙虚线框），入边标签写"可选"；
- 跳过路径：从上游节点顶 → 上方水平绕行 → 下游节点顶，`cls="link"` 无箭头，
  标签说明绕行条件（如"无 ChiNode 的管线直通"）；绕行水平段走节点行上方的
  独立高度（如 y40），不与行内边标签共用高度。

### 8.4 侧挂警示/注释节点

主链旁的说明节点（如"不要按端口名称推断 App 用途"）用 `note` 类，
与主节点之间 `cls="link"` 无箭头水平短边连接；不占用主链纵向节奏。

### 8.5 结果回传长边（纵向长流程）

从末节点 `right` → 画布右缘内侧竖直上行（距最右节点 ≥40px）→ 首节点 `right`，
`cls="data"`；标签两行竖排放在竖直段右侧（anchor start）。竖直段不得压任何
泳带标题（标题都靠左，天然安全）。

### 8.6 横向主链的首边标签

链首边常是总线名（如"MIPI CSI-2 YUV422"）：该间隙单独加宽到标签宽+12px，
标签放在连线上方居中；其余无边标签的间隙保持默认宽。
